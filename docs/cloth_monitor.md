# Agent 实时观察页

监控是一个独立的只读进程：读取指定任务目录，通过本地 HTTP/SSE 展示已有记录。
不启动 Codex、worker 或机器人控制进程，不连接 CAN/相机，不调用 MCP，也不写入任务目录。
不需要安装新的 Python 包或前端构建工具。

## 打开页面

在另一个终端进入项目和 `nero` 环境。默认从 `configs/cloth_agent.yaml` 的
`session.output_dir` 读取本轮目录，与 agent 和人工保持命令共用：

```bash
conda activate nero
cd /home/lab404/WHR/dexterous-manip-ws
python -m cloth_agent monitor
```

浏览器打开 `http://127.0.0.1:8765/`。运行中的任务会增量更新；已结束的任务可直接回看。
也可以先启动监控，再用相同目录启动 agent；监控不会预先创建目录或占用记录文件。
其他配置可用 `monitor --config 配置文件`；回看历史记录仍可用 `monitor 历史目录`，显式目录优先。

端口被占用时用 `--port 8766`，或 `--port 0` 让系统分配端口，按终端打印的地址打开。
服务只绑定机器人主机的 `127.0.0.1`；浏览器在另一台电脑时，通过现有 SSH 连接转发对应端口。
监控终端 Ctrl+C 仅结束页面服务，不影响 agent、机器人控制或已经锁定的人工保持。

## 页面内容

| 区域 | 数据与含义 |
| --- | --- |
| 状态栏 | 根据任务记录显示状态、阶段、cell 数量及用时；设备连接标为启动快照 |
| 执行时间线 | Codex 实际输出的文字、工具调用；开始/更新/完成合并为同一张调用卡片 |
| 代码与反馈 | 源码、代码执行结论、运动失败提示、程序输出；内部通信按类型合并并默认折叠 |
| 观测快照 | cell 中 show() 请求展示的全图/裁剪图，标注 cell、观测 ID、相机帧号与裁剪坐标 |
| 诊断信息 | 控制错误、人工保持记录、Codex stderr 和记录读取错误 |

点击时间线卡片查看对应步骤；取消“跟随最新”可停留在历史步骤，恢复勾选后跟随最新 cell。
图片下拉框可独立选择历史快照。服务连接中断后浏览器自动重连，并从文件重建视图。
界面没有执行代码、停止或恢复机器人的按钮，人工停止继续使用独立 `hold` 命令。

时间线优先显示执行系统的 `Cell #N`；`item_9` 等 Codex 内部编号仅放在调用详情中。
系统生成的 Cell #0 标为“启动准备”并置于最前，不计入 agent cell 数量。
即使 Codex 未记录工具结束事件，已保存的 cell 终态也会更新左侧卡片，避免
左侧仍显示“执行中”、右侧却已显示“已中断”。尚不能关联编号时明确显示“等待编号关联”。

## 正确理解反馈

cell `completed` 只表示 Python 正常返回，不能解释为运动成功。
运动结果来自 cell 返回时的控制快照；控制请求 `ok` 只表示请求返回。
例如 move_L 返回 planning_failed 时 Python 仍可能正常结束，页面会单独标红。
若 planning_failed 只存在 stdout 或返回值的文字中，界面明确标为“文本提示”，
不把文字分析冒充结构化硬件反馈。原始结果始终可展开查看。

反馈区默认优先展示“代码执行完毕 / 代码异常中止”、异常原因和规划失败提示。
控制快照标注为“最近一次已提交运动”，可能属于本 cell 前面成功的动作，
不能覆盖后续未提交动作的规划失败。程序输出保留原文；无表达式返回值时不显示空返回值区。

大量 `motion_status` 是对同一运动的进度查询，不是重复发送运动指令。
这些记录现在合并为“内部通信记录 · N 次请求，其中 M 次运动进度查询”，默认收起。
展开后按类型查看次数与累计请求往返时间；失败请求仍在主反馈区显示。
往返时间不是机械臂运动耗时，原始 JSON 中保留逐条请求顺序和时间。

此版本只观察现有记录，不在执行链路中增加进度事件：

- Codex 提交工具调用时即可看到代码；其公开说明在对应事件写入后显示。
- worker 的 stdout/stderr、robo 调用记录通常在整个 cell 返回后才可见。
- 图像是 agent 请求展示的观测快照，不是持续相机视频；附图错误会单独显示。
- 当前选中 cell 无新图时，图片区域明确标记正在显示其他 cell 的已有快照。
- 任务状态与控制反馈均为最后记录，不是进程存活或机器人健康状态的实时检测。

服务约每 0.4 秒检查记录变化。半行 JSONL、尚未写完的结果文件会留待下一次读取，
不会将暂时不完整的内容当作执行失败。没有原始 Codex 事件的 serve 会话也可查看 cell 记录。

## 源码与验证范围

`cloth_agent/monitor.py` 提供只读文件读取、SSE 和观测 PNG；
`cloth_agent/monitor_assets/` 保存无外部资源依赖的 HTML/CSS/JavaScript。
CLI 的 monitor 分支不导入 TaskSession 或机器人控制模块。

本轮仅做 Python/JavaScript/页面资源的静态检查；没有启动监控或 agent、运行测试、
进行浏览器联调或连接硬件。新页面的运行效果仍需首次使用时确认。
