# 第一版折布 Agent 实施计划

## 目标与边界

实现一个独立 Python 入口，驱动 Codex 在同一个 thread 中完成任务分解、规划、代码生成、执行与异常恢复。

第一版采用两臂依次动作。每个子任务由 agent 生成一份有完整主流程的普通 Python 程序，自行组织动作、监督和异常恢复；固定运行库提供所需工具和底层执行能力。运动期间，程序安排监督函数持续检查状态，发现异常后中断运动并保持姿势。关键点模块、抓取手型和标定参数预留接口，先通过假设备和录制观测验证软件闭环。

## 实施步骤

### 1. 建立独立入口和最小运行接口

新增 `cloth_agent/` 包和 `configs/cloth_agent.yaml`，复用现有 Nero、L20、IK 与 RGB-D 相机封装，保持现有遥操作入口可用。

- Python 主程序启动本机 `codex app-server`，通过 stdio 驱动一个任务 thread，接收工具调用和执行事件；沿用本机 Codex 登录及模型配置。[官方接口文档](https://learn.chatgpt.com/docs/app-server)
- 为 agent 提供观测、几何计算、运动规划、子任务提交、执行事件等待、恢复回复和任务放弃工具。
- 子任务提交工具保存程序及初始参数，并以普通 Python 脚本方式启动；生成的程序通过导入工具库使用运动、观测和通信接口，启动器负责进程生命周期与结果收集。
- 观测统一包含 RGB-D、内参、机械臂与手的反馈、时间戳，以及可选关键点。
- 预留 `KeypointProvider`，本轮不开发识别和跟踪算法；测试使用录制或构造的输入。
- 手型、TCP 偏置、相机及双臂外参先设为空。实机执行前检查相应参数，缺失时明确报告缺项。

### 2. 实现两种路径规划及统一执行器

waypoint 表示虚拟 TCP 目标位姿，统一使用任务坐标系，长度为米、角度为 rad；根据对应机械臂和手型的标定变换，换算到法兰目标。

- **关节空间方式：** waypoint 求 IK，再连接关节路径。
- **笛卡尔空间方式：** 先插值 TCP 位姿，再逐点求 IK，使用上一点的解作为 seed。
- `move_J` 使用关节插值，`move_L` 使用 TCP 直线与姿态插值；复杂路径支持 agent 选择上述两种方式。
- 初始运动在执行前准备为 `MotionPlan`，包含所属机械臂、关节路径和 TOPPRA 时间参数化结果。
- 规划检查覆盖数值有效性、关节限位、IK 误差、连续性及已配置工作区；失败返回位置与原因，供 agent 修改 waypoint。
- 所有运动统一通过本地执行器向 `move_js` 发送目标，默认沿用 20 Hz，不再让 SDK 为这些路径重新规划。
- `move_J`、`move_L` 和关节轨迹执行均支持异步启动并返回运动句柄，以及等待运动完成。句柄提供完成查询、等待结果和暂停保持接口，供生成的程序自行组织监督与恢复。
- 第一版不实现通用避障搜索。速度、加速度上限来自明确配置；假设备测试使用独立测试值。

执行器只允许一个机械臂推进运动。正常完成以轨迹结束且实际关节反馈到位为准，默认沿用 `0.02 rad` 到位容差和 `30 s` 到位等待超时。

### 3. 实现并行监督与原程序恢复

每个子任务由 agent 提交一份可作为脚本运行的完整 Python 程序，提前定义初始参数和轨迹，自行编写主流程、辅助函数、监督条件与恢复分支。固定运行库不要求 `policy(ctx, params)`、`monitor(state, history)` 入口，也不统一启动任务级监督线程。

程序与工具的职责确定为：

- 程序可异步启动运动，并在自己编写的监督循环中读取最新观测和检查异常；也可自行组织并发监督。提供等待下一次观测的辅助工具，监督循环默认参考 20 Hz，具体检查时机由程序安排。
- 运动句柄反映实际运动结果；监督循环退出后仍通过等待结果确认运动到位或获知执行失败。
- 固定执行器是机械臂目标的唯一发送者。程序通过运动工具提交目标，通过暂停保持接口请求中断，不直接发送底层关节命令。
- 程序检测到异常后先调用暂停保持工具；执行器停止推进原轨迹，读取当前关节反馈并持续发送固定保持目标，L20 保持现有抓持命令。
- 程序通过 `request_agent` 类通信工具发送异常原因、当前 state、图像和运动进度，并等待回复；等待期间程序继续存活，设备保持姿势。
- agent 只通过既定回复接口提交新参数或放弃命令。原程序的已有恢复分支使用新参数，从当前实际姿态重新规划并继续执行。
- 子任务运行及等待恢复期间，拒绝替换或重新提交该子任务程序；允许 agent 通过规划、计算工具确定新的恢复参数。
- 监督代码错误和运动超时可由程序已有异常分支处理；未处理异常或意外退出时，由运行库暂停活动运动并报告失败。

生成程序的结构示意如下。工具现已通过 `cloth_agent.tools` 提供，省略的轨迹、手型和监督条件由 agent 在执行前确定；这不是强制模板：

```python
APPROACH = ...
LIFT = ...
CLOSE_HAND = ...


def supervised_lift(trajectory):
    motion = execute_trajectory(trajectory, wait=False)
    while not motion.done():
        state = observe()
        if grasp_lost(state):
            motion.pause_and_hold()
            reply = request_agent(reason="布角滑脱", observation=state)
            if reply["action"] == "abort":
                return False
            new_trajectory = plan_from_current(reply["waypoints"])
            motion = execute_trajectory(new_trajectory, wait=False)
        wait_next_observation()
    motion.wait()
    return True


execute_trajectory(APPROACH)
set_hand_pose(CLOSE_HAND)
success = supervised_lift(LIFT)
```

保持策略先通过假设备验证，再进行低速实机验证。软件验收要求异常触发后下一个控制周期不再推进原轨迹；实际停止延迟与位置偏差通过实机记录确认。

### 4. 接通自动任务循环

实现以下完整流程：

`观测 → agent 制定阶段目标 → 调用计算和规划工具 → 生成完整子任务程序 → 程序执行并自行组织监督 → 通过既有分支恢复或返回结果 → 进入下一阶段`

- 首次观测后，agent 给出任务阶段列表；每阶段结束后根据最新 state 规划下一阶段。
- 正常完成、暂停恢复、程序错误和主动放弃分别反馈，避免把异常退出当作任务完成。
- 任务结束后生成执行总结；保存子任务源码、参数、轨迹、事件及关键图像，供检查与后续改进。
- 演示任务默认设为平铺矩形抹布连续折叠两次，折叠次数允许配置。
- 同步在 `docs/closth_agent.md` 中补充上述接口和实现顺序，保留原项目说明结构。

## 测试与验收顺序

1. **几何与规划：** 验证 TCP/法兰转换、两种规划方式、IK 连续性、规划失败反馈，以及 TOPPRA 速度和加速度约束。
2. **假设备执行：** 验证完整脚本能够异步启动运动并自行监督，覆盖正常到位、运动失败、异常打断、暂停保持，以及另一臂不推进运动。
3. **恢复闭环：** 注入异常，验证脚本通过既有通信接口请求 agent、接收新参数并从当前状态继续；验证源码不变、运行期间不能替换程序，以及未处理错误时的暂停收尾。
4. **独立入口联调：** 使用假设备和录制观测，让真实 Codex thread 完成至少两个阶段及一次异常恢复。
5. **实机分级验证：** 参数填写后依次验证单臂运动、打断保持、两臂交替、抓放和连续两折；沿用现有实机预检与启动确认。
6. **回归检查：** 运行受影响的硬件封装、IK 和相机测试，确认现有遥操作功能仍可使用。

## 预留项与交付条件

- 关键点识别与跟踪、具体抓取手型和标定工作由后续模块提供；本轮交付消费接口、配置占位和测试替身。
- 依赖关键点的任务监控必须收到对应输入后才能用于实机验收。
- 先交付可独立运行、可观测、可打断、可恢复的软件闭环；参数与关键点模块接入后，再完成实际折布验收。

## 当前实现与验证进度

- 已提供独立入口、两种路径规划、TOPPRA 定时和单臂依次执行的后台执行器。
- 已提供普通 Python 脚本工具库、运动句柄、程序自行组织的监督和同进程参数恢复；运行或恢复等待期间不能替换程序，未处理失败结束当前任务。
- `configs/cloth_agent.yaml` 已填写右臂实机参数和候选标定；`demo` 自动选用独立的 `cloth_agent_mock.yaml`。关键点仅提供外部输入接口，支持 `task` 坐标及经相机外参转换的 `camera` 坐标；可读取现有 RGB-D episode 做离线观测输入。
- `python3 -m cloth_agent.cli demo` 已完成两个软件阶段和一次注入异常；`demo --with-codex` 已由真实 Codex 在同一 thread 中生成、执行两个程序并完成一次恢复。
- 回归及新增测试覆盖规划、到位、打断保持、单臂限制、源码与进程不变、程序失败、放弃、RGB-D 输入及 Codex 工具协议。运行说明和依赖安装见 [README](../README.md#折布-agent-与普通-python-程序)。
- 右臂 TCP、手型和相机外参已接入规划、观测和几何工具；实机定位精度、暂停保持、抓取和连续折布尚未验证，另一条臂与关键点模块仍待接入。
