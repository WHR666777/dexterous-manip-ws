# Cloth Agent 架构：codex exec + MCP + 独立持久 Python worker

## 1. 任务与架构基线

让 agent 使用 Nero + LinkerHand L20，将已平铺的矩形抹布折叠

本轮决定重新搭建 agent 主调用链：

- 使用 `codex exec` 启动任务，由 Codex 组织观察、规划、写代码、执行反馈和下一轮决策；一个任务使用同一 Codex 会话，不为每个 cell 重新启动 Codex。
- 使用 MCP 连接 Codex 与本地任务服务。
- 使用独立、持久的 Python worker **进程**执行生成的 cell；任务内保留变量、函数和 `robo` 代理。
- 使用独立的机器人控制**进程**持有 Nero/L20 设备连接、管理运动、读取反馈与处理人工停止保持。
- 人工停止保持通过专用本地通道直接到达机器人控制进程，**不经过 Codex、MCP 队列、cell 执行队列或普通动作队列**。

`PyRUA-Lean/` 仅作为源码参考，不安装为运行依赖，不在其中开发 Nero adapter。现有硬件封装、标定、几何、IK 和 TOPPRA 可以经检查后提取复用；旧 Runtime、app-server 动态工具和脚本参数回信不再作为新框架的兼容约束。

当前 MCP 暂时保留 `python`、`finish`；第一版 robo 的收敛接口见第 5、6 节及机器人操作文档。
MCP 工具协议的后续调整不改变进程隔离和人工保持通道。

## 2. 进程与控制权

```text
启动协调进程（可承载 MCP 服务）
    ├─ 启动、监测和结束本次任务，汇总记录
    ├─ codex exec 进程：思考、生成 cell、调用 MCP、读取反馈
    ├─ 持久 Python worker 进程：执行 cell，保留 globals 和 robo 代理
    └─ 机器人控制进程：设备连接、动作准入、执行器、反馈、停止状态

普通调用：
Codex ↔ MCP 服务 ↔ Python worker ↔ 机器人控制进程 ↔ Nero / L20
                       │                 │
                       └─ 计算与任务监督  └─ 观测、运动结果与设备状态

人工停止保持：
人工本地入口 ── 专用通道 ──> 机器人控制进程 ──> 发送普通 J 固定关节目标并监督反馈
                                     └─ 锁定任务，拒绝后续普通命令
```

| 组件 | 职责与边界 |
| --- | --- |
| 启动协调进程 / MCP 服务 | 装载任务、配置和提示词，启动各进程，分发 cell，收集结果；不再充当第二个折布规划 agent |
| Codex | 根据图像与状态决策、写代码；不持有硬件连接，不承担固定周期控制 |
| Python worker | 保存任务内 globals，执行串行 cell、几何计算和任务级监督；通过 `robo` 代理请求机器人能力，不直接打开 CAN/设备 SDK |
| 机器人控制进程 | 唯一设备连接与目标发送所有者；负责运动准入、轨迹复核/执行、反馈、暂停保持、人工保持锁定与命令拒绝；不执行模型生成的任意源码。IK/TOPPRA 计算在 worker 内完成 |
| 人工保持入口 | 独立接收操作者触发并直接通知控制进程；不等待模型回复或 cell 返回；触发设备动作仍由设备所有者执行 |

规划、图像处理、落盘及普通请求等待不能占住人工保持处理路径。具体 IPC、内部计算调度、MCP 传输和人工输入设备在实现设计时确定，但不能改变上述隔离与优先级要求。

进程隔离使 worker 卡住时控制进程仍可处理停止；它不保证整台计算机、控制进程或 CAN 故障时保持仍能生效。现场物理急停作为独立保障，其作用范围按设备说明与现场验证确认。

## 3. 持久 cell 与任务闭环

```text
RGB-D / state → 阶段目标 → cell（计算、规划、动作、监督）
             → 代码输出、动作结果、状态、图像 → 下一 cell → 任务结束
```

一个任务一个 worker，一次只运行一个 cell。变量和函数保留在 worker 内存，普通 cell 完成不退出进程。MCP 的连接状态不等于 Python 环境生命周期。

- cell 无固定 `policy/monitor` 或 `run(robo)` 入口，可定义函数、条件和有限局部重试。边界由何时需要模型重新看现场决定，不要求一个 cell 完成一整折。
- 每个运动段下发前确定参数并完成规划检查；上一段改变现场后，可重观测再规划下一段，不要求提交源码前规划整个子任务的所有路径。
- 普通运动默认等待结果；运动中需要任务监督时，可在当前 cell 内异步启动并检查句柄。固定库处理设备、运动状态与到位，生成代码处理任务条件。
- **cell 返回 Codex 前，不允许仍有该 cell 提交的轨迹继续推进。** 遗漏等待、代码异常或监控中断时，由控制进程执行暂停收尾并报告是否确认；不能把未确认的设备状态写成“已保持”。
- globals 的修改及已发生的物理动作不会回滚；恢复不能把旧 pose、旧 plan 或旧抓持判断当作现场真值。


## 4. 普通暂停、任务终止与人工位置保持

普通暂停停止推进轨迹，读取实测关节作为固定保持目标。cell 收尾确认后可重新观察并规划。
worker/Codex 退出、超时、预算用尽等结束本次任务，不恢复旧轨迹。

人工 `hold` 通过独立 Unix socket 进入控制主线程，先锁定动作权限，再捕获一次实测关节，
发送一次普通 J 固定位置目标，随后以配置周期监督反馈。绕过 MCP/cell/普通请求队列，只有单次 SDK 发送互斥，
防止普通轨迹帧与保持帧交错；不声称在途 SDK 调用可撤回或存在硬实时停止时限。
重复 hold 不重新捕获目标。失败记录 hold_failed，不自动使能、reset 或改用阻尼急停。

Nero SDK 的 `electronic_emergency_stop()` 被定义为阻尼急停，现场已观察到机械臂下落。
因此 cloth agent 禁用旧 `estop`，人工悬停不能调用该接口。

人工保持时取消 worker/Codex 后，控制进程继续保持，不能跟随任务收尾被自动 terminate/kill。
只有现场确认机械臂安全落座或已有外部支撑，人工 `release-hold` 并输入 `SUPPORTED` 后才能
停止位置下发、断开控制进程；它不清动作锁、不恢复任务。旧会话必须重启后使用新版协议。
L20 不自动松手/reset。agent 无权触发人工释放或复位。

`hold-status` 读取人工模式、固定目标、发送结果与反馈稳定证据。
`hold_confirmed` 不代表独立硬件停机确认；CAN/供电/使能/进程故障时不能保证悬停。
新模式需先在外部支撑条件下验证，详见 [人工保持联调](cloth_estop_test.md)。

## 5. Waypoint、虚拟 TCP 与运动

**运动函数的规划位置以 L20 食指、拇指闭合接触点作为虚拟 TCP；agent 主要使用食指和拇指进行近似 gripper 的 top-down 抓取。**

TCP 固定于工具，开手后也不随指尖位置重定义。已有轴定义：参考姿态下 Z 向下、X 沿法兰旋转轴的水平投影、Y = Z × X，之后固定在工具上。张开手型来自官方预设，闭合手型来自 replay 标定。

第一版只公开 `move_J(target_tcp, wait=True)` 与 `move_L(target_tcp, wait=True)`，
两者都接收 task 系虚拟 TCP 位姿（4×4 SE(3) 或 xyz-rpy，m/rad），不要求 agent 提供关节角。
`move_J` 读取当前关节，转换 TCP 为法兰目标并求一次 IK，再发送一次最终关节 PTP 目标；
不保证 TCP 中途直线。`move_L` 沿 TCP 路径插值求 IK，由普通 J 分段近似执行。
不提供独立 IK 或 plan/execute；规划在 move 内完成。启动回记录关节保留内部关节入口。
`top_down_pose(xyz, yaw)` 用标定参考姿态构造目标，
旋转为 `Rz_task(yaw) @ R_initial_grasp`；yaw 是相对约定初始抓取姿态绕 task +Z 的增量，单位 rad，
不是绝对法兰 yaw，也不随当前 cell 重新锚定。初始抓取姿态保留记录起始关节位姿的法兰位置/yaw，
roll/pitch 采用标定的示教参考。开启 `startup.enabled` 后，宿主先回记录关节，再到该抓取姿态，
确认 TCP 反馈后才启动 Codex；固定准备 cell 000 不占模型 cell 预算，人工 hold 全程可用。
开合手只操作食指和拇指。坐标、单位、TCP、参考姿态、工作区及手型随启动 prompt 提供，
没有 `robo.info()`。具体约定见 [机器人操作说明](../cloth_agent/robot_operations.md)。

## 6. 观测与抓布反馈

`state()` 读取实际状态；`observe()` 返回带标识的固定 RGB-D 快照与关联状态；
`show(obs, crop=None)` 通过 MCP 返回实际图像；`pixel_to_task(obs, pixel)` 使用同一快照反投影。
第一版不提供抓布判定接口，agent 再次观察现场图像来判断效果。运动到位、SDK 返回、手位置反馈
都不能替代抓布成功证据。普通 `pause_and_hold(reason)` 确认保持后结束当前 cell，允许新 cell 重新观察恢复。

## 7. 当前实现、实施范围与预留项

目前仅允许使用右手 Nero + L20。

### 基础进程框架与 robo 第一版（2026-10-25）

主流程统一放在 `cloth_agent/`，通过 `python -m cloth_agent` 启动。已有独立持久 worker、独立控制进程、专用人工位置保持 Unix socket、任务协调器，以及临时 MCP / `codex exec` 入口。
本阶段接入上述 robo、右臂/右手控制与 L515 观测。默认不连接设备；指定 `--execute` 后直接连接，无交互确认。
人工入口在硬件模式下捕获固定关节目标并发送普通 J 保持、持续监督反馈；hold_target_sent 只表明调用返回，stop_confirmed 仍为 false，新版实际悬停效果尚未验证。旧阻尼急停入口已禁用。

按用户要求，本轮仅写代码并检查语法，不执行 mock、单元测试或真实模型/设备联调。代码阅读顺序、依赖与命令见 [框架说明](cloth_framework.md)。

旧 agent 主流程及其专用执行/观测后端和对应测试已删除，不保留 framework 子包或脚本参数回信兼容层。已有几何、独立规划和标定配置接入当前 TaskSession/robo。
