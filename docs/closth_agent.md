# Cloth Agent 架构：codex exec + MCP + 独立持久 Python worker

## 1. 任务与架构基线

让 agent 使用 Nero + LinkerHand L20，将已平铺的矩形抹布折叠

本轮决定重新搭建 agent 主调用链：

- 使用 `codex exec` 启动任务，由 Codex 组织观察、规划、写代码、执行反馈和下一轮决策；一个任务使用同一 Codex 会话，不为每个 cell 重新启动 Codex。
- 使用 MCP 连接 Codex 与本地任务服务。
- 使用独立、持久的 Python worker **进程**执行生成的 cell；任务内保留变量、函数和 `robo` 代理。
- 使用独立的机器人控制**进程**持有 Nero/L20 设备连接、管理运动、读取反馈与处理人工电子急停。
- 人工电子急停通过专用本地通道直接到达机器人控制进程，**不经过 Codex、MCP 队列、cell 执行队列或普通动作队列**。

`PyRUA-Lean/` 仅作为源码参考，不安装为运行依赖，不在其中开发 Nero adapter。现有硬件封装、标定、几何、IK 和 TOPPRA 可以经检查后提取复用；旧 Runtime、app-server 动态工具和脚本参数回信不再作为新框架的兼容约束。

MCP 工具清单、名称、参数、结果 schema，以及 `robo` 的具体方法签名留待后续讨论。PyRUA-Lean 的 `python`、`finish` 是参考，不在本文中冻结最终工具协议。

## 2. 进程与控制权

```text
启动协调进程（可承载 MCP 服务）
    ├─ 启动、监测和结束本次任务，汇总记录
    ├─ codex exec 进程：思考、生成 cell、调用 MCP、读取反馈
    ├─ 持久 Python worker 进程：执行 cell，保留 globals 和 robo 代理
    └─ 机器人控制进程：设备连接、动作准入、执行器、反馈、停止状态

普通调用：
Codex ↔ MCP 服务 ↔ Python worker ↔ 机器人控制进程 ↔ Nero / L20
                       │                 │
                       └─ 计算与任务监督  └─ 观测、运动结果与设备状态

人工电子急停：
人工本地入口 ── 专用通道 ──> 机器人控制进程 ──> Nero 电子急停接口
                                     └─ 锁定任务，拒绝后续普通命令
```

| 组件 | 职责与边界 |
| --- | --- |
| 启动协调进程 / MCP 服务 | 装载任务、配置和提示词，启动各进程，分发 cell，收集结果；不再充当第二个折布规划 agent |
| Codex | 根据图像与状态决策、写代码；不持有硬件连接，不承担固定周期控制 |
| Python worker | 保存任务内 globals，执行串行 cell、几何计算和任务级监督；通过 `robo` 代理请求机器人能力，不直接打开 CAN/设备 SDK |
| 机器人控制进程 | 唯一设备连接与目标发送所有者；负责运动准入、规划/执行、反馈、暂停保持、急停锁定与命令拒绝；不执行模型生成的任意源码 |
| 人工急停入口 | 独立接收操作者触发并直接通知控制进程；不等待模型回复或 cell 返回；触发设备动作仍由设备所有者执行 |

规划、图像处理、落盘及普通请求等待不能占住急停处理路径。具体 IPC、内部计算调度、MCP 传输和人工输入设备在实现设计时确定，但不能改变上述隔离与优先级要求。

进程隔离使 worker 卡住时控制进程仍可处理停止；它不保证整台计算机、控制进程或 CAN 故障时电子急停仍能送达。现场物理急停作为独立保障，其作用范围按设备说明与现场验证确认。

## 3. 持久 cell 与任务闭环

```text
RGB-D / state → 阶段目标 → cell（计算、规划、动作、监督）
             → 代码输出、动作结果、状态、图像 → 下一 cell → 任务结束
```

一个任务一个 worker，一次只运行一个 cell。变量和函数保留在 worker 内存，普通 cell 完成不退出进程。MCP 的连接状态不等于 Python 环境生命周期。

- cell 无固定 `policy/monitor` 或 `run(robo)` 入口，可定义函数、条件和有限局部重试。边界由何时需要模型重新看现场决定，不要求一个 cell 完成一整折。
- 每个运动段下发前确定参数并完成规划检查；上一段改变现场后，可重观测再规划下一段，不要求提交源码前规划整个子任务的所有路径。
- 普通运动默认等待结果；运动中需要任务监督时，可在当前 cell 内异步启动并检查句柄。固定库处理设备、运动状态与到位，生成代码处理任务条件。
- **cell 返回 Codex 前，不允许仍有该 cell 提交的轨迹继续推进。** 遗漏等待、代码异常或监控中断时，由控制进程执行暂停收尾并报告是否确认；不能把未确认的设备状态写成“已保持”。
- globals 的修改及已发生的物理动作不会回滚；恢复不能把旧 pose、旧 plan 或旧抓持判断当作现场真值。


## 4. 普通暂停、任务终止与人工电子急停

| 情况 | 机器人侧行为 | 后续处理 |
| --- | --- | --- |
| 普通任务监控中断、可恢复代码错误 | 停止推进轨迹，使用反馈执行暂停保持，保留现有 L20 抓持命令 | 保持确认且 cell 收尾后，可由下一 cell 恢复 |
| worker 超时/退出、Codex 退出、连接丢失、预算用尽或主动放弃 | 控制进程撤销任务动作权限，执行普通暂停收尾；失败如实记录 | 第一版结束任务，不自动恢复旧轨迹 |
| 人工电子急停 | 急停锁定，废止普通待执行动作，停止轨迹及常规保持目标下发，向已配置 Nero 发电子急停请求 | 任务终止，禁止 agent 自动复位、使能或继续动作 |
| 设备/控制进程故障或停止无法确认 | 不声称已经停住；能够处理时拒绝新动作并记录故障 | 需人工处置，不能仅凭模型或进程退出恢复 |

人工电子急停的处理约束：

1. 人工请求直接进入控制进程的专用处理路径，不等待 MCP/cell/普通动作串行锁，也不等下一个普通 20 Hz 轨迹周期。
2. 进入锁定状态，使进行中的轨迹、排队动作和迟到请求失效；普通运动与持续保持命令不得在急停后恢复下发。
3. 向所有已配置 Nero 请求电子急停。急停发送不等待 worker/Codex 退出，记录每侧发送、失败和可用反馈；“请求已发送”与“停机已确认”分开报告。
4. 随后取消任务并终止必要的 worker/Codex 进程。模型不能清除急停锁；人工恢复流程与启动新任务分开，不续播旧命令。
5. Nero 急停不自动覆盖 L20。L20 在人工急停时的设备能力与停止/保持策略需要单独确认；不能假定双臂急停会让手一起停止，也不默认松手或 reset。

现有 [NeroArm.emergency_stop](../robot_control/nero.py) 映射 `Driver.electronic_emergency_stop()`，发送后返回，不等待停止确认；现有文档还提示急停后的 reset 可能导致机械臂下落。它可作为适配起点，不能单凭函数返回宣称设备已停止。

电子急停发送、停止确认、实际运动停止之间的延迟与偏差需要实机测量。普通 20 Hz 调度、独立进程、发送成功或清理代码执行完，都不能单独构成停止时限保证。

任务的正常结束也要由宿主与控制进程实际收尾、拒绝后续动作、保存结果。PyRUA-Lean 的 `finish` 主要记录声明，不能直接照搬为实机结束保证；最终入口形式留待工具设计。

## 5. Waypoint、虚拟 TCP 与运动

**运动函数的规划位置以 L20 食指、拇指闭合接触点作为虚拟 TCP；agent 主要使用食指和拇指进行近似 gripper 的 top-down 抓取。**

TCP 固定于工具，开手后也不随指尖位置重定义。已有轴定义：参考姿态下 Z 向下、X 沿法兰旋转轴的水平投影、Y = Z × X，之后固定在工具上。张开手型来自官方预设，闭合手型来自 replay 标定。该 TCP 已经被标定过，agent 可直接使用类似于 gripper 的 top-down 抓取，在抓取时，一般只需规划 虚拟 TCP 的位置、yaw 角（绕 task +Z 旋转，或者说 x 轴朝向？）即可。

## 7. 当前实现、实施范围与预留项

目前仅允许使用右手 Nero + L20。

### 基础进程框架第一步（2026-10-25）

主流程统一放在 `cloth_agent/`，通过 `python -m cloth_agent` 启动，提供独立持久 worker、独立控制状态进程、专用人工急停 Unix socket、任务协调器，以及临时 MCP / `codex exec` 入口。本轮不实现 robo、运动、观测和设备连接；控制进程没有连接 Nero/L20，人工入口只锁定框架状态，明确返回硬件未连接、停机未确认，不代表实机电子急停已实现。

按用户要求，本轮仅写代码并检查语法，不执行 mock、单元测试或真实模型/设备联调。代码阅读顺序、依赖与命令见 [框架说明](cloth_framework.md)。

旧 agent 主流程及其专用执行/观测后端和对应测试已删除，不保留 framework 子包或脚本参数回信兼容层。几何、独立规划和标定配置保留，尚未接入当前 TaskSession。
